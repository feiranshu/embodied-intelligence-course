## 2. 语音功能

终端会先打印模型真实转录结果，例如：

```text
语音转录：向前 移动
```

明确的标准指令直接解析；其他表达交给 DeepSeek 理解为结构化动作，再核对动作名称、方向和距离。终端会打印“理解结果”。例如“帮我往前挪一点”“给大家打个招呼”“回到立正姿态”可以分别表达末端移动、挥手和姿态恢复，不需要背固定句式。支持的动作范围：

| 指令 | 行为 |
|---|---|
| 立正、抬起 | 调用同名已记录姿态 |
| 向左转、向右转 | 底座持续转动，直到停止或已校准边界 |
| 挥手、招手 | 播放 `actions.挥手` 序列 |
| 向前/后/左/右/上/下移动 | 沿基座坐标轴持续小步移动，直到停止、边界或不可达 |
| 向前移动五毫米、向上移动五厘米 | 按转录中的距离分段移动；`max_distance_mm` 默认 200 mm |
| 停止、急停、停下 | 中断当前动作，清除运动状态 |

“前”是基座 +X，“左”是基座 +Y，“上”是 +Z。它们不会随腕部朝向改变。

在 Windows 用户环境变量中设置 `DEEPSEEK_API_KEY` 后重新打开终端。`advanced.json` 的 `llm` 指定 DeepSeek 接口和模型；可用 `ARM_LLM_URL`、`ARM_LLM_MODEL`、`ARM_LLM_API_KEY` 覆盖。接口使用 [DeepSeek Chat Completions](https://api-docs.deepseek.com/)；密钥不写入源码或交付包。

缺少方向、未知动作、混合多条或超限指令会给出澄清或“不执行”；模型理解不保证完全正确。未说距离时持续运动，说“一点”时移动 5 mm，明确距离则按距离移动。新的持续方向指令先停止旧动作再切换方向，不排队。模型请求在独立线程处理，实时部分转录识别到“停止/急停/停下/别动了”时请求停止，并丢弃尚未执行的模型结果。单步目标先校验限位，通信或到位反馈异常会停止。软件停止沿用释放扭矩行为，请托住可能下落的连杆。

小型转录模型仍可能听错，语言模型也不能可靠恢复所有错误转录。先在模拟模式检查实际麦克风、环境噪声、转录文本和理解结果。不能保证语音停止的实时性，Ctrl+C 和物理电源仍应可用。

选择麦克风：

```powershell
.\.venv\Scripts\python.exe -m sounddevice
.\.venv\Scripts\python.exe -X utf8 advanced.py --simulate voice --device 1
```

使用本包提供的合成中文测试录音：

```powershell
.\.venv\Scripts\python.exe -X utf8 advanced.py --simulate voice --wav verification\voice_forward.wav
```

`verification/voice_*.wav` 由 Windows Huihui 语音合成，仅用于可复现的软件验证，不是现场麦克风验收录音。

## 3. 实机准备与姿态记录

### 手动校准安全范围

校准逐关节记录舒适参考姿态为零点；提示“正在连续采样”后，缓慢移到第一端点，再经过实际活动路径移到第二端点。程序约每 40 ms 读取一次，累计相邻读数的跨零变化，不再把每个端点独立折到 ±512。`joint_mapping` 保存 `zero_raw`、方向 `sign`、边界 `limits` 和 `unwrapped`，运行时根据已采集区间选择映射分支。跨度接近完整反馈周期或采样间跳变过大时拒绝保存，不能靠两个端点猜测走过哪段圆弧。底座左负右正；例如零点 1022 时，696→−326、1022→0、0→2、295→297，边界内缩后为 [−323,294]。这些是反馈计数，不是已验证的连续机械角度。

跨零关节禁止原始位置姿态/IK 输出；关节连续控制使用速度方向命令和映射反馈限位，不向舵机发送跨零的位置目标。实机启动要求：完成范围采样、在原网页显式切换相应关节到连续模式，并通过现场低速测试确认 `wheel_positive`（原控制器的 `left` 或 `right` 哪个使映射读数增加）。未确认时该字段为 null，禁止启动；不猜测方向，也不自动改写模式。反馈反向、突跳过大或 0.8 秒不再前进会停止。此保护不能证明电位器盲区可安全跨越，仍需现场验证。

```powershell
.\.venv\Scripts\python.exe -X utf8 advanced.py calibrate-ranges
```

窗口持续等待用户操作，不自动计时结束。此入口只读寄存器，要求六关节扭矩均已关闭。托住机械臂，按提示逐关节摆到两侧安全工作端点，按 Enter 采样；不要用电机顶到机械硬限位，也不要手动硬掰。两端点之间应连续可通行、不碰撞、不拉紧线缆。程序将端点内缩 3 格，采样期间检查是否摆稳，每个关节完成后需放回范围内部。六关节完成后，输入 SAVE 才保存 `limits_raw`、`joint_directions` 和 `motion_calibrated=true`；中途取消不覆盖配置。

保存后可用 `advanced.py --execute voice` 测试底座持续左右转动。底座每次最多改变 3 格，读取到位反馈后继续，到边界自动停止；“停止”中断运行。前后、上下等末端平移仍需第 4 节的运动学校准。逐关节限位不等于整臂碰撞检测；预设姿态/动作仍需单独示教和检查运动路径。

实机使用 SCS215 协议。进阶位置控制要求六关节处于位置模式；程序不会自动修改 EEPROM。原网页仍保留连续旋转控制。

1. 运行原包的 `diagnose.py`，核对 ID 1～6 和实际模式。
2. 在原网页由操作者显式选择“全部恢复位置模式”，然后关闭网页控制器，释放串口。
3. 检查 `advanced.json` 中的 `limits_raw`。它初始沿用旧包记录的端点，必须按当前装配核对，确认每个关节的可用范围后设置 `motion_calibrated: true`。
4. 保持总线供电、扭矩释放，并托住机械臂摆出各个姿态；用下面的命令记录。`record` 只读取反馈，不使能扭矩、不写模式、不驱动机械臂。

```powershell
.\.venv\Scripts\python.exe -X utf8 advanced.py record "立正"
.\.venv\Scripts\python.exe -X utf8 advanced.py record "抬起"
.\.venv\Scripts\python.exe -X utf8 advanced.py record "向左转"
.\.venv\Scripts\python.exe -X utf8 advanced.py record "向右转"
```

实际记录写入 `advanced.json` 的 `poses`，每个姿态包含按 ID 排列的六个原始位置值。覆盖同名姿态需加 `--overwrite`。当前保留了已有“立正”采样；“抬起”“向左转”“向右转”仍需示教。动作开始前检查全部引用姿态，缺少任何一步便拒绝执行。

`actions.挥手` 已定义“抬起 → 向左转 → 向右转 → 向左转 → 立正”。每一步可设置 `duration_s`、`pause_s`，以及可选的 `speed`；未设置速度时使用全局 `speed`，初值 100。

位置运动逐个关节执行，启动下一个关节前读取反馈确认上一个到位，静止关节保持位置。`duration_s` 平分给本步需要运动的关节；实际耗时还受速度上限、通信和反馈等待影响，不承诺严格实时或多关节同步。超时、通信故障或停止会中断后续步骤；程序退出会请求停止全部并释放扭矩，操作者应托住机械臂。

完成记录后运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 advanced.py --execute text "立正"
.\.venv\Scripts\python.exe -X utf8 advanced.py --execute text "挥手"
.\.venv\Scripts\python.exe -X utf8 advanced.py --execute keyboard
.\.venv\Scripts\python.exe -X utf8 advanced.py --execute voice
```

`keyboard` 打开键盘窗口：按住 `W/S/A/D/R/F` 分别控制末端前/后/左/右/上/下，松键停止；空格、Esc、窗口失焦或关闭窗口均停止。数字键调用界面列出的姿态和动作；模拟模式中 `1～4` 是四个姿态，`5` 是挥手。预设动作按完整序列执行，可以用空格中断。定距输入框默认 50 mm，点击六个方向按钮执行相应距离；编辑输入框时不触发方向快捷键。

需要终端输入时使用 `advanced.py --simulate console` 或 `advanced.py --execute console`：输入指令并回车执行，`stop` 停止，`q` 退出。原网页的按住/松键连续旋转行为保持原样。

## 4. 末端控制的运动学标定

现有网页新增“末端直线运动 · 1.2”：距离默认 50 mm，点击六个方向按钮执行定距移动；勾选“启用末端键盘”后，按住 W/S、A/D、R/F 分别控制前后、左右、上下，松键、空格、Esc、失焦和网页心跳中断均停止。未启用末端键盘时保留原关节快捷键。运动期间不接受其他姿态或关节命令；完成后显示请求位移和根据反馈计算的模型估计位移，遇到无解时显示可行方向的移动结果。实机运动学标定未完成时，末端按钮不可用。

拍摄实机六方向演示时，先关闭原控制器，在本目录运行 `.\.venv\Scripts\python.exe -X utf8 controller.py --cartesian-view`。浏览器自动打开只显示六方向控制的页面，末端键盘已启用；按住对应键时方向按钮亮起，松开即请求停止。镜头同时拍到机械臂、键盘和界面，依次展示 W/S（前后）、A/D（左右）、R/F（上下），最后按空格停止。此入口连接实机，仍需要完成下面的运动学标定。若只使用独立键盘窗口，关闭网页控制器后运行 `.\.venv\Scripts\python.exe -X utf8 advanced.py --execute keyboard`，不要同时运行两个串口控制程序。

默认模型读取随源码提供的 `so101_new_calib.urdf`，来源是课程指定的 [SO-ARM100 / SO101 模型](https://github.com/TheRobotStudio/SO-ARM100/blob/main/Simulation/SO101/so101_new_calib.urdf)。程序使用关节原点、固定旋转、转轴、限位和 `gripper_frame_joint` 工具偏移，不需要下载 STL，也不调用官方 STS3215 驱动。URDF 的米转换为毫米，串口仍由原有 SCS215 协议实现。

URDF 描述几何，不提供这台 SCS215 的原始读数与几何角之间的对应关系。现有 `zero_raw` 及旧包的 `home` 不能视为已确认的 URDF 零角。实机前应核对装配与 URDF 一致，并测量以下参数：

| 字段 | 定义 |
|---|---|
| `urdf` | 相对本项目目录的模型路径，当前为 `so101_new_calib.urdf` |
| `zero_raw` | ID 1～5 在各自参考几何角处的原始读数，五个值 |
| `reference_angles_deg` | 对应参考姿态的五个 URDF 关节角，省略时全为 0；可在安全弯曲姿态测量，不必把实物强行摆到零角 |
| `directions` | ID 1～5 原始读数增大是否使 URDF 角度增大：+1 或 -1 |
| `degrees_per_raw` | SCS215 的角度编码比例，初值 300/1023 度/格 |
| `joint_mapping` | 使用 1.1 已测得的六关节零点、符号和映射限位；跨零范围按已记录的连续分支展开 |
| `limits_raw` | 没有完整 `joint_mapping` 时使用的原始读数工作区间 |

角度换算为 `q = reference_angles + (unwrap(raw) - unwrap(zero_raw)) × directions × degrees_per_raw`，计算时转换为弧度。`unwrap` 使用 1.1 的关节映射展开反馈读数，使 1023→0 的相邻移动保持连续；逆解量化后再转换回 0～1023。映射参考零点与 URDF 几何零角是不同的测量值，不能直接互相替代。FK 按 URDF 关节链相乘 `T = T_origin,1 Rz(q1) … T_origin,5 Rz(q5) T_tool`，取平移部分作为夹爪工具坐标。默认前/左/上是 URDF 基座的 +X/+Y/+Z，需要现场用 FK 和小幅运动核对。

IK 使用位置雅可比的阻尼最小二乘：`Δq = Jᵀ (J Jᵀ + λ² I)⁻¹ (目标位置 - FK(q))`。从当前关节角附近迭代，在实测限位与 URDF 限位的交集内求解；必要时尝试邻近的弯肘初值。末端平移使用前四个关节，腕旋转和夹爪开合保持当前值，工具俯仰不强制固定。输出量化为 SCS215 整数读数后复核位置误差，拒绝一次超过 45 格的关节跳变。未配置 `urdf` 的旧四关节平面模型仍使用原来的余弦定理解法及 `lengths_mm`、`base_height_mm`、`shoulder_offset_mm`。

直线规划使用 `p(s) = p_start + s × Δp`，定距命令拆成不超过 5 mm 的段，段内每约 1 mm 求一次 IK；执行时每轮每关节最多改变一格，并保持原工程一次仅运动一个关节的约束。正常路径的后续目标基于原始直线计算，避免累计量化漂移。整数反馈和逐关节执行会产生小幅阶梯误差，不能承诺数学意义上的连续精确直线或严格完成时间。

若目标无解，终端打印“IK 无解”，在当前关节附近的限位内搜索小步，选择能朝原方向前进、且更接近期望位移的可行解，再继续同方向运动。没有可行前进方向时停止，不会无限重试或反向绕行；边界调整后实际距离可能小于请求值。定距运动完成时打印请求位移和 FK 实际位移。

IK 沿用 1.1 的映射限位和逐关节反馈执行；需要跨反馈零点时，沿用已验证的连续模式方向，缺少该方向会停止。当前 ID 1、4 尚未记录 `wheel_positive`，涉及这两个关节跨零的路径不能执行；不跨零的工作区间不需要补测该方向。核对 URDF 参考角、角度方向、位置模式和 FK 后，才设置 `kinematics.calibrated: true`，重启控制器并先检查小幅末端运动。现有标定配置未被自动修改。模型不提供碰撞检测。

## 5. 黑球视觉闭环

支持桌面固定相机跟随和末端相机闭环两种方式。固定相机默认控制夹爪朝向，也可使用末端平移模式；末端相机使用下面的图像雅可比标定。

### 桌面固定相机：屏幕黑球跟随

退出语音或其他机械臂控制程序后，双击 `start_vision.bat`，自动打开黑球网页。右侧控制栏提供启动、停止、回位和夹爪方向按钮，不需要切换到相机窗口。固定摄像头，使左侧白色区域和完整黑球清晰可见；右栏显示识别状态。

首次使用，先点击 **朝前准备**：保留底座当前方向，上臂回位后腕部会分段向前倾斜，避免停留在夹爪几乎竖直的通用初始姿态。先核对实际屏幕方向，再点击 **开始四点对准**。黑球依次出现在左上、右上、右下、左下；每个位置都用右栏的左转、右转、抬起、压低按钮，让夹爪实际指向黑球，再点击 **已指向黑球，保存此点**。每次调整约 5°，勾选“精细调整”后约 1°。四点完成后保存相机像素与实际关节朝向的对应关系，**启动跟随**才会启用；姿态未改变、点位退化或超出范围的记录会拒绝保存。准备姿态本身不代表已经指向黑球。

点击 **启动跟随** 后拖动黑球。鼠标只移动显示目标，机械臂的目标来自真实摄像头识别结果与已保存的四点映射，不使用网页鼠标坐标代替视觉识别。底座与腕部配合转向，夹爪开合保持不变；超过已对准区域时限制在区域边界，并在右栏提示。动作仍受原有关节范围、相对基准各方向 25°和单段约 5°的限制。每次最多 80 段或 120 秒，到上限停止后可以再次启动。

点击 **停止运动** 或按空格/Esc 停止；切换或关闭页面、页面连接中断也会停止。**退出控制**释放相机和串口。四点记录保存在 `advanced.json` 的 `vision.pointing_calibration`；挪动摄像头、屏幕或机械臂后必须重新对准。该映射依据人工指向样本插值，实际准确度要在屏幕中间位置检查，不能把保存记录当成整屏精度验收。若按钮到关节边界仍无法指向，应调整机械臂和屏幕的相对摆放。

旧相机窗口操作仍可通过去掉启动参数 `--web` 使用；仅使用末端平移时还需去掉 `--point-at-ball`，保留原来的每像素 0.2 mm、每步最多 10 mm、死区 25 像素、总位移 60 mm。

仅检查相机、不连接机械臂：`python vision_control.py --fixed-camera`。固定模式不需要末端相机的图像雅可比，但仍要求已有机械臂运动学标定和合法初始姿态。

### 末端相机

相机安装后，在电脑屏幕打开课程文档的黑球图片，让黑球清晰可见且周围背景干净。先只预览检测，不访问串口：

```powershell
.\.venv\Scripts\python.exe -X utf8 vision_control.py
```

当前相机配置为索引 1；连接相机或设备枚举顺序变化后应重新核对索引。

红圈是检测到的目标，绿色十字是图像中心，不需要手工把黑球对齐中心。可在 `advanced.json` 的 `vision` 中调整灰度 `threshold`、`min_area` 和 `min_circularity`。算法使用灰度阈值、形态学操作、轮廓面积/圆度筛选；球被画面边缘裁切时，排除图像边界上的直线段，利用剩余圆弧拟合椭圆估计球心。拟合需通过形状误差和至少约 120° 圆弧覆盖检查。目标完全不可见、可见圆弧太少或存在大小相近的多个圆时，不会继续发出运动命令。预览时可以自由移动相机，按 Q、Esc 或空格退出。

### 标定图像与运动方向

确认机械臂和运动学已经标定、相机固定好、运动区域空旷后执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 vision_control.py --execute --calibrate
```

这条命令会实际运动：分别沿 `control_axes` 指定的两个基座轴移动约 5 mm，再回到原姿态。默认 `[1,2]` 对应基座 Y、Z，适用于相机大致朝向基座 X 前方；若相机主要朝下，通常应选择 `[0,1]`，并重新标定。

程序用实际 FK 位移和黑球像素位移估计 2×2 图像雅可比 J，检查反馈是否足够、两个方向是否可区分，成功后保存相机索引、实际分辨率、J 和 `calibrated: true`。标定时黑球、屏幕和相机支架必须保持固定；失败时停止，不覆盖旧结果。

### 自动跟踪

```powershell
.\.venv\Scripts\python.exe -X utf8 vision_control.py --execute
```

每轮检测黑球偏离中心的像素误差 e，以 `Δp = -gain × J⁻¹ × e` 计算受限的小步位移，经 IK 和位置反馈执行后，再读取新画面。默认每步最多 3 mm，误差进入 12 像素死区并保持若干帧后停止。它在所选两个轴构成的平面内向目标方向调整，不估计黑球深度，也不执行接触或抓取。

目标突跳、相机断开、误差持续增大、距启动位置超过 60 mm、80 次迭代或 120 秒超时都会终止。窗口内按 Q、Esc、空格，关闭窗口，或终端 Ctrl+C 都会停止。相机安装角度、分辨率、控制轴或初始工作区域明显改变后应重新标定。软件停止受图像读取、串口超时影响，不能替代现场断电。
