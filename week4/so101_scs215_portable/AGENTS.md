# 项目工作规则

## 目标与验收

- 当前项目是六关节 SCS215 机械臂的课程控制程序。任务以用户当前要求和课程文档为准，旧交接记录只作为参考。
- 1.1：预设姿态、预设动作和切换时间/速度控制。1.2：根据 URDF 和实测关节映射求解 IK，通过键盘控制末端前后、左右、上下走直线及指定距离。
- 1.2 的无解处理须明确反馈，并在关节范围内尽可能保留原请求方向。不能把单关节运动冒充末端直线运动。
- 验收依赖实际位置反馈和实机运动效果。编译通过、模拟通过、目标寄存器写入成功都不能代替实机到位；模型计算的末端距离不能冒充外部测量结果。
- 用户要求修复时，持续完成定位、修改、检查和已授权验证；不要只列下一步或要求用户反复执行同一个失败动作。

## 硬件与运动控制

- 硬件为六只 Feetech SCS215，报告型号 8965；不要套用 STS3215 的寄存器、编码分辨率或校准值。SCS 16 位数据采用高字节在前。
- 串口使用配置和自动识别，不硬编码本机 Python 路径或端口。只能有一个程序占用控制串口。
- 多关节姿态和 Cartesian 运动可以同步执行；是否分阶段取决于实际路径、碰撞风险和跨零要求，不实行全局单关节限制。
- 使用实测关节范围和跨零方向。保留已验证的跨零路径及必要回位顺序，不能为了通过测试扩大限位或直接跳过跨零保护。
- 速度、行程、输出和到位容差分别依据任务与反馈设定，不强制速度 100、极短点动或固定微小步长。不要把速度参数当成力矩参数。
- 无进展、振荡或超时时，检查实际目标、位置、输出和控制参数，区分通信、控制和机械问题；不得靠无限重试、反复重发目标或延长超时掩盖失败。
- 保留反馈、看门狗和取消处理。1.2 失败后停止整组运动；停止是否成功必须核对驱动关闭反馈，失败时如实报告。
- 不为消除报错而屏蔽舵机故障状态，不将未证实的硬件原因作为结论。

## 授权与自主执行

- 已授权范围内的代码修改、只读检查、服务维护和可逆操作自主完成，不为每个步骤重复询问。
- 实机运动前确认操作者在场、运动范围清空，并明确目标、边界和停止条件。已确认的条件在同一连续调试中适用，除非用户撤回、环境改变或动作超出授权范围。
- 用户明确只允许一次动作时，不扩展为多次试验。常规编码和只读定位继续进行，不因运动授权受限而停止全部工作。
- 启停控制器属于已授权调试的配套操作；重启前确认无动作运行、驱动已关闭，避免多个程序争用串口。
- EEPROM 持久修改、整组模式切换和未经验证的运动范围变更须有对应授权。保持 EEPROM 锁定的临时控制参数与永久配置修改应明确区分。
- 未要求并行代理时不启动子代理。

## 修改与验证

- 修改前读取相关代码和配置；README.md 和 HANDOFF.md 中的历史描述须与当前实现、用户要求核对，不能机械照搬。
- 坚持最小差异，保留无关行为；不要借修复重构、改名、重新格式化或添加无关依赖。
- 改控制逻辑时，针对真实故障建立回归检查，并确认该检查能区分修复前后；不要仅验证模拟舵机会照抄目标。
- Python 修改后执行语法检查，包含 controller.py、servo_bus.py、diagnose.py 和改动文件；协议改动运行 test_offline.py，运动逻辑改动运行相关 test_advanced.py 测试。
- JSON 修改后校验实际修改文件。必要检查通过后，仅在新增修改、失败或未解决疑点时追加检查，不用反复跑测试代替定位。
- 完成前审查最终差异，移除与用户要求或必要修复无关的修改。
- 报告区分已经修复的代码问题、实机已验证结果和仍未解决的问题。不得把“已停止”或“已增加诊断”表述为任务完成。
