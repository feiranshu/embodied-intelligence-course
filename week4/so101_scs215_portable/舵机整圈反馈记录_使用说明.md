# 单舵机转动与原始反馈记录

## 1. 为什么增加这个程序

已检查 week4 的 `calibration.py`、`joint_mapping.py` 和 `advanced.py`。

- 已有串口协议、按键运动所需的连续模式控制、停止回读和看门狗，可直接复用。
- 已有 `PositionTrace` 把相邻反馈按 1024 展开，但单次变化超过 128 格或累计跨度达到 1000 格时会中断，不适合本次观察整圈反馈。
- 原有范围采集主要保存零点和端点，不保留完整原始序列；也没有证明 SCS215 在反馈端点以外仍能准确测角。

因此新增 `record_servo_rotation.py`，复用 `servo_bus.py`，不修改旧的关节映射、FK 或采集程序。本程序记录原始反馈，不根据这些反馈估算“已完成360°”，不按旧映射限位、端点值或读数突跳拒绝记录。

## 2. 准备与启动

先关闭任务二网页对应的 Python 服务，以及其他占用机械臂串口的控制器。只关闭浏览器标签页不一定释放串口。

打开 **PowerShell**，依次执行下面的命令。这里直接调用本机 Conda 的 `py312` 环境，无需先激活环境或初始化 PowerShell 的 Conda 插件：

```powershell
$servoPython = 'D:\software\anaconda\envs\py312\python.exe'
Set-Location -LiteralPath 'C:\Users\sfr08\Desktop\本学期课程\具身智能\embodied-intelligence-course-main (1)\embodied-intelligence-course-main\week4\so101_scs215_portable'
& $servoPython .\record_servo_rotation.py --id 5 --speed 150 --set-wheel-mode
```

后续命令都在**同一个 PowerShell 窗口、同一个程序目录**执行，复用上面设置的 `$servoPython`。如果重新打开窗口，请先重新执行前两行。PowerShell 中，`&` 用于执行变量中保存的程序路径；切换目录使用 `Set-Location`，不使用 `cd /d`。

上面选择 **ID5 腕部旋转**。改变 `--id` 即可指定另外一个舵机：

| ID | 关节 |
|---|---|
| 1 | 底座 |
| 2 | 肩部 |
| 3 | 肘部 |
| 4 | 腕部俯仰 |
| 5 | 腕部旋转 |
| 6 | 夹爪 |

串口默认按原配置自动识别。需要明确指定时，例如：

```powershell
& $servoPython .\record_servo_rotation.py --id 1 --port COM8 --speed 150 --set-wheel-mode
```

程序仅依赖 Python 标准库与项目原有的 `pyserial`。若环境提示缺少 serial：

```powershell
& $servoPython -m pip install -r .\requirements.txt
```

移动到另一台电脑后，把 `$servoPython` 改为该电脑对应环境的 `python.exe` 路径，并把 `Set-Location` 的路径改为实际工程目录。程序内部没有硬编码本机 Python 路径或串口。

### 关于 --set-wheel-mode

该参数明确允许把**选定的一个舵机**切换为连续模式。它会涉及该舵机的 EEPROM 角度限制寄存器；程序先保存原始限制，正常退出时恢复原值并锁定 EEPROM。若本来已经是连续模式，不会重新设置模式。

如果不希望程序切换模式，去掉该参数；此时选定舵机必须已经处于连续模式，否则会报错退出。

程序不使其他关节运动，也不改变其他关节的扭矩状态。选定关节松键后会释放扭矩，需要托稳会受重力下落的连杆。装配后的部分关节、尤其夹爪，不能机械转满一圈；以实物可达运动和线缆状态为准，不要强行绕过机械阻挡。

## 3. 键盘怎么用

保持运行程序的终端窗口在前台，先松开所有方向键，再开始：

| 按键 | 功能 |
|---|---|
| 按住 ← | 选定舵机沿一个方向持续转动 |
| 按住 → | 沿相反方向持续转动 |
| 松开方向键 | 停止并释放选定舵机扭矩；继续记录 |
| 同时按住两个方向键 | 停止 |
| 空格 | 停止；松开方向键后才能重新启动 |
| 切换到其他窗口 | 停止；回来后需松开方向键再重新按住 |
| M | 在日志中留下一个人工观察标记 |
| Q / Esc | 停止、结束采集、恢复原模式限制并保存结果 |
| Ctrl+C | 中断并执行同样的退出清理 |

左右方向沿用原控制器的 `left/right` 定义，具体实物顺逆时针取决于舵机安装朝向。速度是控制参数，不是已知的角速度。

开始与结束均不会自动回位。

## 4. 建议如何完成这次观察

1. 在输出轴或连杆上选一个能看清的物理参考方向，程序开始后先静止记录一小段。
2. 按 M 标记起点。
3. 按住一个方向键，观察实物转动与终端读数；读数即使一直为0或1022，程序也会继续逐次记录。
4. 如果确认轴还在转而数值不变，可松开方向键，按 M 留下标记，再继续。可以同时录制能看到实物与终端的视频，方便判断标记对应的实际运动。
5. 实物完成一圈，或完成该装配关节可达范围的往返后，松键，再按 M 标记终点。
6. 按 Q 退出，保留整个输出文件夹。

**不要把原始读数回到起点当成实物完成一圈的证据。** 这次正是在验证原始反馈和真实运动之间的关系。

## 5. 生成什么文件

默认保存在程序所在目录的：

```text
rotation_records/
  id5_日期_时间_微秒/
    positions.csv
    serial_and_events.jsonl
    session.json
```

### positions.csv：每次位置读取一行

可用 Excel 或文本编辑器打开。包含：

| 字段 | 含义 |
|---|---|
| sample | 连续采样序号 |
| utc | 本次请求的 UTC 时间 |
| request_started_s / reply_finished_s | 相对于会话起点的实际请求/回复时间 |
| read_ms | 本次交易耗时 |
| joint | 被读取的舵机ID |
| command_direction | 当时程序发出的方向，或 stopped |
| speed_parameter | 速度参数；不是角速度，也不代表实物一定运动 |
| raw_position | 通过协议校验且无舵机故障码的位置值 |
| raw_candidate | 8字节回复中按位置字段提取的候选值；包错误时也保留，但不可视为可信位置 |
| within_0_1023 | 是否在常见数值范围内；只标记，不裁剪、不删行 |
| status_byte | 舵机返回的状态/故障字节 |
| reply_hex | 实际收到的原始回复字节 |
| error | 超时、包长度错误、校验失败或舵机故障等 |

**所有重复值、端点值、突跳值都保留。失败也占一行，不用上次读数填补，不为读取位置自动重试。** 停止转动后仍继续采集，直到退出。

### serial_and_events.jsonl：原始通信与人工标记

每行一个 JSON，记录实际发送、接收的字节，以及运动、停止、M键标记和错误。原控制库在运动命令中发生的重试，其串口收发也会记录。清理串口缓冲区前发现的迟到数据也会写入日志，不当作成功位置填入CSV。

### session.json：会话摘要

记录端口、舵机ID、原始模式/角度限制、样本数、读取错误数，以及停止和模式恢复是否得到确认。模式切换前就会保存原始限制，便于意外断电后的追溯。

## 6. 采样频率与“全部记录”的范围

默认每秒尝试采样50次，可改为：

```powershell
& $servoPython .\record_servo_rotation.py --id 5 --speed 150 --hz 100 --set-wheel-mode
```

实际速率受串口往返、命令收发和磁盘写入影响，以CSV里的实际时间为准。每行会立即刷新到文件，不做抽样、均值处理或去重。

“全部记录”指本程序每次位置请求得到的结果，以及它实际收到的通信字节。舵机内部在两次请求之间的所有变化无法保证捕获，USB驱动之外未到达主机的数据也无法记录。程序不会因为反馈跨度接近一圈而中断。

通信错误或舵机故障会停止当前运动，但采集继续、错误保留。只有反馈恢复正常且方向键已松开，才能重新按键运动。原有看门狗仍保留。

## 7. 只记录，不由程序驱动

如果只想记录已释放扭矩的舵机、由你手动观察其运动：

```powershell
& $servoPython .\record_servo_rotation.py --id 5 --record-only
```

此模式只读取，不设置模式、不切换扭矩、不发运动命令；Ctrl+C结束。程序不会代你释放原先已开启的扭矩。

也可以指定记录30秒后结束：

```powershell
& $servoPython .\record_servo_rotation.py --id 5 --record-only --duration 30
```

## 8. 常见情况

- **打不开串口：** 退出其他占用串口的Python服务，再检查USB、外接电源和端口。
- **提示尚非连续模式：** 添加 `--set-wheel-mode`，或使用原控制器将该舵机切为连续模式后再运行。
- **按键无效：** 确保程序所在终端是前台窗口，松开方向键后重新按住；发生读取错误时先查看错误是否已经恢复。
- **启动后一直为0/1022：** 不会因此阻止采样，观察实物是否真的转动，并用M标记。
- **停止/恢复失败：** 终端会明确打印 `STOP NOT CONFIRMED` 或 `MODE RESTORATION FAILED`，具体信息在 `session.json` 中。不要将这种会话当作已正常停止或恢复。
- **强制结束进程/断电：** 不能保证退出清理执行；已写出的日志保留，但模式可能尚未恢复。重新使用前核查模式与 `session.json` 中的原始限制。
