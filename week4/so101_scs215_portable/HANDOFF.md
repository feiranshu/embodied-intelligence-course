## 项目目标

## 协议摘要

数据包格式：

```text
FF FF ID LENGTH INSTRUCTION PARAMS... CHECKSUM
CHECKSUM = ~(ID + LENGTH + INSTRUCTION + PARAMS...) & 0xFF
```

本项目使用的寄存器：

| 地址 | 用途 |
|---:|---|
| `0x09` | 最小角度限制，高字节在前 |
| `0x0B` | 最大角度限制，高字节在前 |
| `0x28` | 扭矩开关 |
| `0x2C` | 连续模式方向/速度，高字节在前 |
| `0x30` | EEPROM 锁 |
| `0x38` | 当前原始位置，高字节在前 |

连续模式配置：最小/最大角度限制均为 `0`。位置模式恢复值为 `0/1023`。运行值 `100～1000` 是一个方向，`100～1000 + 1024` 是反方向；`0` 停止。

## 软件结构与设计决策

- `servo_bus.py` 是唯一直接访问串口的模块。
- `controller.py` 同时提供静态网页和同源 JSON API，不需要 Node.js。
- 单关节点动按单关节执行；多关节姿态和末端控制允许同步执行，按运动路径保留必要的跨零顺序。
- 松键、窗口失焦、页面隐藏、空格和程序退出都会请求停止。
- 运行时网页每 250 ms 发送心跳；服务端约 0.8 s 收不到心跳会停止当前舵机。
- LAN 模式监听 `0.0.0.0`，每次运行生成随机令牌；本机模式只监听 `127.0.0.1`。
- 串口默认自动按 CH343 `VID:PID=1A86:55D3` 识别，可用配置或 `--port` 覆盖。
- `diagnose.py` 使用 `stop_on_close=False`，因此是严格只读检查。
- `config.json` 保留了曾测得的位置端点，仅供追溯；连续模式控制器不使用这些端点。

## 对后续 agent 的操作约束

1. 按 AGENTS.md 的授权规则执行；已授权范围内自主完成调试，不逐步重复确认。实机运动遵守已确认的现场条件和动作范围。
2. 不要把官方 STS3215/LeRobot 的寄存器和校准假设直接套到模型 8965。
3. 修改串口逻辑后，先使用模拟串口或单元测试验证，再连接实物。
4. 实物运动按已确认的目标、范围和停止条件执行；速度与步长依据反馈确定，多关节任务不强制拆成单关节极短点动。
5. 不要同时启动多个控制器。出现 `PermissionError(13)` 时先查端口占用，不要反复重试。
6. 整组模式切换和 EEPROM 持久修改需要对应授权；已验证跨零流程按其授权范围执行，不额外要求重复网页确认。

## API

本机模式不要求令牌；LAN 模式要求 URL 查询参数 `token` 或请求头 `X-Control-Token`。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 进程和串口信息 |
| GET | `/api/state` | 读取六只舵机位置、模式和限位 |
| POST | `/api/mode` | `{"id":"all","mode":"wheel"}` 或 `position` |
| POST | `/api/run` | `{"id":1,"direction":"left","speed":100}` |
| POST | `/api/heartbeat` | `{"id":1}`，维持当前连续旋转命令 |
| POST | `/api/stop` | `{"id":"all"}` 或单个 ID |

## 当前状态的确认方法

舵机 EEPROM 模式可能因用户后续操作改变，不应只相信文档。接手后运行：

```bat
python diagnose.py
```

输出中 `min=0, max=0` 表示连续模式；其他值表示位置模式。该命令不会修改 EEPROM、扭矩或速度。
