# 同类机械臂公开标定结果检索

检索日期：2026-10-16。通过公开网页、GitHub 文件树、原始文件和历史版本核对。第三方源文件仅作阅读参考，没有运行其中的控制程序。现有项目标定配置未被这些参考值替换。

## 结论

找到了 SO-101 的实际手眼矩阵、带像素误差的拟合示例，以及已从主分支删除的历史标定报告。也找到了同型号 SCS215 的逐点角度标定表。但没有核实到与本机 SCS215 改装机械臂、GENERAL WEBCAM 和相机安装位置完全一致的标定结果。

## 1. so101-keyboard-typer：完整相机到末端矩阵

仓库：https://github.com/ardacinardemirtas/so101-keyboard-typer

核对版本：`a8236e0ee8e40cf489ad0efd0428788854597c52`。

[实际运行脚本中的矩阵](https://github.com/ardacinardemirtas/so101-keyboard-typer/blob/a8236e0ee8e40cf489ad0efd0428788854597c52/src/so101_keyboard/click_to_move.py)，换算为平移毫米后：

```text
T_EE_CAM =
[[-0.99938712,  0.02241607,  0.02688672, -9.42822],
 [-0.03310399, -0.85490033, -0.51773502, 60.81714],
 [ 0.01137988, -0.51830777,  0.85511845,-38.62474],
 [ 0,           0,           0,           1       ]]
```

方向为 `p_ee = T_EE_CAM @ p_cam`；原文件平移单位为米。平移向量长度计算为 **72.6601 mm**。

同一提交的 [hand_eye_constants.py](https://github.com/ardacinardemirtas/so101-keyboard-typer/blob/a8236e0ee8e40cf489ad0efd0428788854597c52/src/so101_keyboard/hand_eye_constants.py) 又保存了另一组矩阵，平移 `[-6.058, 68.949, -57.824] mm`，长度 **90.1902 mm**。仓库没有在这两个文件中解释差异。不能将两组结果视为对同一安装的独立一致验证。

作者注释称结果经多个求解器核对；这不构成我们已验证其物理精度。已核对文件中没有与这组常量直接配套、可复算的实测绝对误差报告。项目 README 明确要求为自己的安装重新标定。

## 2. RAX：14视角、10.55 px 的实际拟合示例

[公开 JSON](https://github.com/arminforoughi/RAX/blob/7ed20483a268fa6e36f28b569978b4ad937498c2/examples/handeye_so101.example.json)：

```json
{
  "tf": "-0.0140,-0.0854,-0.0417,-0.8057,-0.0210,0.0627",
  "rms_px": 10.55
}
```

前三项为米，后三项为旋转向量、单位弧度，不是欧拉角。平移为 `[-14.0,-85.4,-41.7] mm`，长度 **96.0627 mm**。文件注明由一台 SO-101 的14个视角拟合，需要为自己的安装重新拟合。

进一步阅读 [handeye.py](https://github.com/arminforoughi/RAX/blob/7ed20483a268fa6e36f28b569978b4ad937498c2/src/rax/perception/handeye.py)：它使用固定物体中心的多视角投影和指尖像素约束，不是我们的48个棋盘角点联合残差。因此 **10.55 px 不能直接与本机8.84 px排名**。代码还说明，单点目标使相机沿视线方向的位置不易确定。

## 3. LeTyping：恢复已删除的真实报告

主分支的报告链接返回404。通过文件提交历史定位到2026-05-22删除报告的提交，再读取其父版本，成功取得 [历史报告](https://github.com/MatteoR1103/LeTyping/blob/375d270d7eb28296019653552f2fdb4b209a1244/camera_calib/stats/nonlinear_handeye_report.txt)。

| 报告指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 重复一致性均值 | 20.203 mm | 14.366 mm |
| 重复一致性 RMS | 29.279 mm | 22.401 mm |
| 地标位置 RMS | 46.203 mm | 46.497 mm |
| 地标最大误差 | 279.616 mm | 244.848 mm |

报告记录检测样本18/21、稀疏地标37/117，优化终止状态为成功。优化后的 `T_gc` 平移 `[13.18072,33.30292,10.88463] mm`，长度 **37.4338 mm**。完整矩阵在本目录 `letyping_historical_report.txt` 和 `numeric_summary.json`。

这是历史实验，不应解释为项目最新最终精度。重复一致性改善，但地标RMS没有改善，说明优化成功或某一个残差下降不等于真实定位正确。项目当前文档同样要求每套硬件单独标定。

## 4. Fireloop：SO-101腕部相机的公开误差记录

[作者原文](https://www.blog.fireloop.ai/hand-eye-calibration-connecting-robot-vision-to-robot-motion/)记录了固定 ChArUco 板、腕部相机的眼在手上标定。其原型验证误差约从33 mm降至12 mm，改进涉及视角、图像质量和弱帧筛选。

文章给出了固定棋盘位置一致性的均值/最大误差计算示例，但未明确12 mm究竟对应哪一个统计量，不能当作12 mm RMS，更不能直接与本机30.81 mm RMS对比。没有在原文中核实到可直接下载的最终矩阵文件。

## 5. SCS215：同型号逐点舵机角度表

[作者测量过程](https://jgdo.github.io/Servo-Calibration/)及 [真实配置](https://github.com/jgdo/arips_ros/blob/master/arips_launch/config/scs_servo_params.yaml)。该机械臂是 ARIPS Arm v2，不是SO-101，但舵机同为SCS215。

ID3的部分数据：

| 角度 | 反馈读数 |
| --- | ---: |
| -20° | 454 |
| -10° | 492 |
| 0° | 529 |
| +10° | 561 |
| +20° | 592 |

相邻10°对应读数增量38、37、32、31，作者用查表插值处理非线性。各舵机零点不同，不能直接复制到本机。配置原件保存在 `scs215_servo_params.yaml`。

## 对本机结果的意义

1. 同类产品确实有公开结果，但标定值取决于末端坐标定义、舵机安装和相机支架，不能只按产品名复制。
2. 本机8.84 px仍是训练拟合结果。搜索到10.55 px的第三方结果不能证明本机已通过验收，因为目标与残差不同。
3. 本机376.13 mm拟合距离需要实物核对。其他安装的37～96 mm仅是这些样例的数值，不是SO-101的标准距离；如果本机光学原点实际只离对应末端坐标原点几厘米，376 mm就不符合安装几何，不能因为像素误差较低而接受。
4. 同型号SCS215实测资料支持进一步核对每个关节的读数与真实角度关系，不能仅凭无端点异常就假设全程线性。

## 本地文件

`sources.json` 保存下载地址和SHA256；大多数SO-101来源已固定提交版本。SCS215配置来自master，文件哈希保留了本次取到的版本。`numeric_summary.json` 是从常量中解析矩阵、按平移向量长度计算的数值摘要，没有执行外部源代码。
