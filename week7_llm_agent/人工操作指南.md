## 10. 4.2：把已有功能封装为 Agent Functions

4.2 使用 `robot_tools.py` 定义工具 Schema 和实现，使用 `agent_loop.py` 完成“模型提出工具调用 → 本地执行 → 工具结果返回模型 → 模型继续回答”的循环。可用工具不少于任务书要求的三个，包含状态读取、姿态、动作、关节、小车相机视觉、目标检测、追踪、动作模仿和停止等能力。


需要展示模型自主选择运动工具时，去掉 `--read-only`，但先保持模拟模式，不加 `--execute`。终端会打印每次 `→ 调用工具` 和 `← 结果`，日志保存在 `runs\agent_时间\tool_calls.json` 与 `transcript.json`。

## 13. 常见问题

### 智谱返回 429 / 1305

```text
该模型当前访问量过大，请您稍后再试
```

这是免费模型服务拥堵，不是 API Key 或照片错误。客户端会自动在 3 秒和 8 秒后重试；三次仍失败时停止，保存包含 `ok: false` 和错误原因的 `log.json`，且不会移动机械臂。稍后重新运行原命令，不要高频循环请求。

### `ModuleNotFoundError: No module named 'numpy'`

说明当前终端没有激活课程根目录的虚拟环境。执行：

```powershell
cd "D:\about learning\Term 3.1\具身智能引论"
& ".\.venv\Scripts\Activate.ps1"
cd ".\第7周_LLM_Agent_代码_20261019\第7周_LLM_Agent\week7_llm_agent"
```

确认提示符出现 `(.venv)` 后重新运行原命令。

### API 调用显示 `Connection error`

先确认浏览器能打开服务商网站，并检查代理、防火墙或当前程序的联网权限。这种错误发生在连接阶段，不能单凭它判断 Key 错误；程序会停止且不移动机械臂。

### 找得到摄像头但无法读取画面

先关闭 Windows 相机、浏览器视频页面、会议软件和其他 Python 进程。确认 USB 线没有因调整机械臂而松动，再重新枚举设备。若名称方式瞬时失败，可在确认索引后重试 `--camera 1`。

### 摄像头画面颠倒、过曝或模糊

这是物理取景问题，不用改模型：旋转镜头、避开直射屏幕和灯、移开手指或支架，并在拍摄时保持机械臂静止。

### 回到初始状态时报到位超时

实测已确认 ID4 不再触发跨零错误。一次动作中 ID4 曾被其他关节机械阻挡；阻挡解除后 ID4 可通过。随后 ID3 在目标 `300` 附近稳定于 `288～289` 并触发严格到位保护。程序会关闭全部驱动。不要连续反复硬顶；先检查是否仍有机械干涉，再决定重录姿态或单独调整运动时序/到位容差。不要修改 EEPROM。

### 舵机运动像抽搐或快速往返

旧姿态3实测时，ID5 从约 `946` 前往 `345` 需要跨零，程序必须在位置模式和连续旋转模式之间切换，并曾出现异常采样保护；姿态3到位后又立即恢复 ID5/ID6，退出时释放扭矩也会导致承重关节回落。这三段动作叠加会看起来像抽搐。新模仿流程不再使用姿态3的自动恢复，并在 ID5 需要跨零时保持当前腕向。若其他关节仍持续抖动，应立即断电并记录具体舵机 ID，不要连续重试。

如果现象是各关节依次运动、每段之间明显停一下，这是旧的逐关节调度造成的“卡顿”，不是舵机来回抖动。当前代码对无跨零目标改用六轴同步下发；实机执行前仍会根据当时的六轴位置重新判断，只有确认整条路径不跨零才使用同步模式。动作结束释放扭矩后的自然回落与运动过程卡顿是两件事，本作业暂不处理回落。
